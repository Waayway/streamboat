# What real music players in each stack look like

Corrected version of `docs/research/tech-stack.md` §6 — two significant reclassifications applied
(Museeks; Supersonic/Feishin scoping below). Use this as a quick "has anyone shipped this stack for a
music player, and did it work" lookup when evaluating a candidate.

**Scoping note (fact-checked correction): Supersonic and Feishin are not TIDAL-client precedents.**
Supersonic talks to Subsonic/OpenSubsonic servers and Jellyfin only; Feishin talks to Navidrome,
Jellyfin and OpenSubsonic-compatible servers. Neither has ever spoken to TIDAL's API — read their rows
below as **stack-and-audio-engine comparators only** (both delegate bit-perfect audio to libmpv, which
is directly relevant to `audio-engine-comparison.md`), not as evidence for manifest handling, quality
cascades, or `subStatus`/session behaviour. Sone, sone-windows, High Tide, tidalt, tidal-hifi and
Strawberry are the rows with actual TIDAL precedent.

| Project | Stack | What it looks like / notable | Source |
| --- | --- | --- | --- |
| **Sone** | Tauri 2 + React 19 + Tailwind 4 + Jotai; Rust/GStreamer audio | Dark, Spotify-shaped: left sidebar, card grids, bottom player bar, now-playing drawer, full-screen player, floating resizable miniplayer, 15 theme presets + full colour picker, synced lyrics, signal-path panel with a "PRISTINE" verdict badge. Repo `github.com/lullabyX/sone`. Screenshots: `ref:sone/data/sone_homepage_readme.png`, `ref:sone/data/sone_drawer_readme.png`, `ref:sone/data/sone_theme_readme.png` | verified from checkout |
| **sone-windows** | Same, plus `wasapi2sink` + `souvlaki` | Identical UI; separate fork, AI-assisted port, and **behind current upstream** (v0.16.0 vs. Sone's v0.21.0 — 15,753 Rust + 28,518 TS/TSX vs. 26,721 Rust + 47,609 TS/TSX) — not a thin per-OS delta | `ref:sone-windows/README.md` |
| **High Tide** | Python + GTK4 + libadwaita + Blueprint | GNOME HIG: `AdwNavigationView`-style pages, carousels, sidebar, `AdwToolbarView`. `flathub.org/apps/io.github.nokse22.high-tide`. Screenshots: `ref:high-tide/data/resources/screenshot 1.png` through `screenshot 4.png` | verified from checkout |
| **Amberol** | Rust + GTK4 + GStreamer | The reference for "small beautiful GTK music player": album-art-derived adaptive background, no library management by design, no metadata editing, no network access. 2026.1 released 2026-04-05 by GTK core developer Emmanuele Bassi. `apps.gnome.org/Amberol` | web |
| **Decibels** | GJS + TypeScript + GTK4 + libadwaita | GNOME audio player with a waveform view | web |
| **Psst** | Rust + druid | Native-widget Spotify client, deliberately plain; author cites druid's reactive architecture as the source of most UI complexity, with Xilem as the intended successor — **date this quote (fact-checked addition): `jpochyla`, `github.com/jpochyla/psst` discussion #359, January 2023**, i.e. it predates iced 0.14.0's reactive-rendering rewrite (2025-12-07) by nearly three years; weight it as evidence against the Elm/druid architecture family circa 2023, not against iced 0.14 specifically. As of Feb 2026 requires the user's own Spotify Developer Client ID | web |
| **Spot** | Rust + GTK4 | GNOME-styled Spotify client, same visual family as High Tide | web |
| **Supersonic** (Subsonic/Jellyfin, not TIDAL — comparator only) | Go + Fyne 2.8; **libmpv** for audio | Dark/light built-in themes, dense grid+list layout; ReplayGain, 15-band EQ, gapless, "optional audio exclusive mode". **v0.22.1** (corrected from v0.22.0), released **2026-08-09** — **correction (fact-checked): a prior draft's staleness caution ("~2 years with no release, verify before citing as actively maintained") was itself wrong.** GitHub renders a current-year release date with no year suffix, which produced the "2024-08-09" misreading; the main-branch `go.mod` requires `fyne.io/fyne/v2 v2.8.0` (released 2026-07-13) via a `replace` directive pinned to a 2026-08-09 fork commit — a 2024 release cannot depend on a mid-2026 package. Supersonic **is** actively maintained; the repo moved to `github.com/supersonic-app/supersonic`. AppImage bundles mpv; Linux needs `libmpv1`/`libmpv2`. Flatpak build "does not support CJK fonts as the sandboxing breaks font lookup". | web |
| **Feishin** (Navidrome/Jellyfin/OpenSubsonic, not TIDAL — comparator only) | Electron + React 19 + Mantine + Zustand + electron-vite; **mpv** for audio | Full Spotify-alike; synced lyrics, smart playlist editor. v1.15.1, 2026-07-19, ~9k stars. Bit-perfect requires `--audio-device=alsa/…`, `--gapless-audio=no`, exclusive mode; Flathub build uses PipeWire and won't do it | web |
| **tidal-hifi** | Electron (castLabs `v43.0.0+wvcus`) wrapping TIDAL's web player | Looks exactly like TIDAL web, because it *is* TIDAL web. Adds MPRIS, an Express HTTP API with Swagger, themes | `ref:tidal-hifi/package.json` |
| **tidalt** | Go + BubbleTea + Lipgloss TUI; FFmpeg + ALSA via cgo | Terminal UI with progress bar and text input; also `tidalt daemon` headless + MPRIS2. Screenshot: `ref:tidalt/docs/tui.png` | verified from checkout |
| **Strawberry** | C++17 + Qt 6.4/6.8 + GStreamer | Classic desktop three-pane collection manager; audiophile focus incl. DSD for local files. **~166,100 lines of C++/headers — the largest codebase in this survey by a wide margin**, not the 14,708 an earlier count gave | `ref:strawberry/` |
| **ncspot** | Rust TUI (cursive) | Terminal Spotify client; the "TUI is enough" data point | web |
| **Cider** | Electron + Vue.js, with Rust components | Apple Music client; visually the most "designed" of the Electron music clients. The rumoured Electron→Tauri migration is **not confirmed** — sources describe it as Electron + Vue.js "utilizing localized Vue.js and Rust" | web (unverified) |
| **Nuclear** | Electron + React | Community music player; proof that Electron ships fast and looks fine | web |
| **Museeks** | **Corrected: Tauri 2 + Rust + React, not Electron.** Ported from Electron to Tauri (announced 2024; README: "Back-end: Tauri v2 / Rust", "UI: React.js") | **A second shipped Tauri 2 + React music player besides Sone — the useful negative control for this whole report's argument.** Its `src-tauri/Cargo.toml` pins `tauri` 2.11.2 but has **no audio crate at all** (`lofty` 0.23.3 for tags, `m3u`, `axum` 0.8.9, `tokio` 1.52.3, `sqlx` 0.8.6) — playback stays in the webview, so it cannot be bit-perfect. That is exactly the split streamboat must not fall into: webview UI, yes; webview *player*, no. Its `sqlx`+`axum` choices independently corroborate the SQLite/local-HTTP sub-decisions in Recommendation 1. Also the source for "Tauri does not support cross-platform binaries, so the command will only generate binaries for your current platform" — see `tauri-engineering-facts.md` §6. It also ships `ts-rs = "12.0.1"` (Rust→TypeScript typegen) and the exact `[profile.release]` block (`codegen-units=1`, `lto`, `opt-level="s"`, `panic="abort"`, `strip`) `tauri-engineering-facts.md` §12 recommends — a shipped precedent for both, not just a docs recommendation. | `github.com/martpie/museeks`, its `src-tauri/Cargo.toml` |

**Avalonia 12's claimed 3× Android performance improvement is web, unverified** — same confidence
tier as the Cider migration rumour above (`avaloniaui.net` was blocked when fact-checked). It is not
a shipped music-player data point in this table but is cited elsewhere in
`references/scoring-and-candidates.md` §2 (4.12).
